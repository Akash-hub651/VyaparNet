## 1. MONOREPO STRATEGY

### Tooling
- **Turborepo**: Task runner with build caching.
- **pnpm**: Workspace-aware package manager.
- **Docker**: Local development parity.

### Structure
```
/ (root)
├── apps/
│   ├── api/                    # NestJS Backend API
│   ├── web/                    # Next.js Buyer PWA
│   ├── admin/                  # Next.js Admin Dashboard
│   └── seller-dashboard/       # Next.js Seller Dashboard
├── packages/
│   ├── shared/                 # Shared DTOs, types, utils (Zod schemas)
│   ├── ui/                     # Shared React components (Design System)
│   ├── eslint-config/          # Custom ESLint rules
│   └── ts-config/              # Shared TypeScript configs
├── infra/                      # Terraform / Pulumi IaC
├── services/                   # Standalone workers (BullMQ)
├── docker-compose.yml          # Local dev stack
├── turbo.json                  # Pipeline config
└── pnpm-workspace.yaml
```

### WHY?
- **Shared Code**: `packages/shared` contains Zod schemas used by ALL frontend and backend apps.
- **Build Caching**: Turborepo caches builds. `api` won't rebuild if `shared` hasn't changed.
- **Independent Deployments**: Each `app` can be deployed independently via Docker.

## 2. MODULE-FIRST ARCHITECTURE

### Philosophy
**Domain-first**, not layer-first.

### WRONG (Layer-First)
```
src/
controllers/
  product.controller.ts
  order.controller.ts
services/
  product.service.ts
  order.service.ts
```

### CORRECT (Domain-First / Modular Monolith)
```
modules/
  orders/
    orders.module.ts
    orders.controller.ts
    orders.service.ts
    orders.repository.ts
    orders.events.ts
    tests/
      orders.service.spec.ts
      orders.controller.spec.ts
  products/
    products.module.ts
    ...
```

### WHY?
- **Encapsulation**: Each module owns its own DB tables, events, and business logic.
- **Testability**: `orders.module` can be tested in isolation.
- **Future Extraction**: When `products` module grows, it can be extracted into a microservice without touching other modules.

## 5. TRANSACTION BOUNDARY DESIGN

### Philosophy
Use Prisma `$transaction` for same-database operations. Use **Outbox Pattern** for distributed transactions.

### DB Transaction (ACID)
```typescript
// For Order Placement
await prisma.$transaction(async (tx) => {
  const order = await tx.order.create({ ... });
  await tx.inventory.update({ data: { quantity: { decrement: qty } } });
  await tx.orderItem.createMany({ data: items });
});
```

### Outbox Transaction (Eventual Consistency)
```typescript
await prisma.$transaction(async (tx) => {
  await tx.order.create({ ... });
  await tx.inventory.update({ ... });
  
  await tx.eventOutbox.create({
    data: {
      eventType: 'OrderPlaced',
      payload: { orderId: 'ord-123' },
      status: 'PENDING',
      deduplicationKey: `order-${orderId}-placed`,
      eventMonth: '2025-05'
    }
  });
});
```

### WHY Outbox?
- If background worker (Queue) is down, DB still persists the event.
- Guaranteed delivery (at-least-once semantics).
- Events are ordered by `createdAt`.

## 6. EVENT-DRIVEN ARCHITECTURE & OUTBOX PATTERN

### Event Bus (In-Memory + Persistent)
```typescript
class EventBus {
  publish(eventName: string, payload: any) {
    // 1. Immediate: Emit to in-memory listeners
    this.emitter.emit(eventName, payload);
    
    // 2. Persistent: Save to Outbox for background workers
    this.saveToOutbox(eventName, payload);
  }
}
```

### Outbox Worker (Processes pending events)
```typescript
async function processOutbox() {
  const events = await prisma.eventOutbox.findMany({
    where: { status: 'PENDING' },
    take: 100,
    orderBy: { createdAt: 'asc' }
  });

  for (const event of events) {
    try {
      await processEvent(event);
      await prisma.eventOutbox.update({
        where: { id: event.id },
        data: { status: 'COMPLETED', processedAt: new Date() }
      });
    } catch (error) {
      await handleRetryOrDLQ(event);
    }
  }
}
```

## 9. AUTHENTICATION & RBAC

### Authentication Flow
```
[User] --> POST /auth/otp/send (phone)
[Server] --> Generate OTP, save to Redis (TTL: 5 min)
[User] --> POST /auth/otp/verify (phone, otp)
[Server] --> Verify OTP, create User if new, return JWT (access + refresh)
[User] --> Sends accessToken in Header for every request
```

### RBAC (Role-Based Access Control)
```typescript
@Permissions('order:create', 'product:delete')
@Roles(UserRole.SELLER, UserRole.SELLER_MANAGER)
class ProductController {
  // Only users with 'order:create' AND role SELLER can access this
}
```

### Permission Map
```
Permissions are defined as: `resource:action`
- `order:create` - Place a new order
- `product:update` - Edit own product
- `inventory:view` - Read inventory levels
- `user:delete` - Admin only
```

## 13. CACHING & INVALIDATION STRATEGY

### Cache-Aside (Look-Aside) Pattern
```typescript
async getProductBySlug(slug: string): Promise<Product> {
  const cacheKey = `product:${slug}`;
  const cached = await this.redis.get(cacheKey);

  if (cached) return JSON.parse(cached); // Hit

  const product = await this.productRepository.findBySlug(slug);
  await this.redis.setex(cacheKey, 300, JSON.stringify(product)); // Miss

  return product;
}
```

### Cache Invalidation (Event-Driven)
```typescript
@OnEvent('ProductUpdated')
async handleProductUpdated(payload: ProductUpdatedPayload) {
  const { productId, slug } = payload;
  await this.redis.del(`product:${productId}`);
  await this.redis.del(`product:${slug}`);
  
  await this.redis.del(`search:trending`);
  await this.redis.del(`search:${productId}:suggestions`);
}
```

## 17. SECURITY HARDENING

### List
- **Helmet**: Secure HTTP headers.
- **CORS**: Whitelist domains only. No `*`.
- **Rate Limiting**: `express-rate-limit` (100 req/min per IP).
- **CSRF**: Double-submit cookie for non-API routes.
- **SQL Injection**: Use Prisma ORM only. No raw SQL injection points.
- **XSS**: Sanitize user-generated content (DOMPurify on frontend).
- **Secure Cookies**: `HttpOnly`, `Secure`, `SameSite=Strict`.

### 22.15 Feature Flag Cache (Redis-Backed)
```typescript
class FeatureFlagService {
  private readonly CACHE_TTL = 300; // 5 minutes
  
  async isEnabled(flagName: string, userId?: string): Promise<boolean> {
    const cacheKey = `feature-flag:${flagName}:${userId || 'global'}`;
    
    // 1. Check local memory (fastest)
    const localValue = this.localCache.get(cacheKey);
    if (localValue !== undefined) return localValue;
    
    // 2. Check Redis (fast)
    const redisValue = await this.redis.get(cacheKey);
    if (redisValue !== null) {
      const parsed = JSON.parse(redisValue);
      this.localCache.set(cacheKey, parsed);
      return parsed;
    }
    
    // 3. Fallback to DB (slowest - avoid this)
    const dbValue = await this.featureFlagRepo.isEnabled(flagName, userId);
    await this.redis.setex(cacheKey, this.CACHE_TTL, JSON.stringify(dbValue));
    this.localCache.set(cacheKey, dbValue);
    return dbValue;
  }
}
```

## 23. OPERATIONAL RUNBOOK (Final Hardening Notes)

> **Purpose**: These 6 operational standards are enforced across ALL backend services, queues, and external integrations.

### 23.1 Request Timeout Standards
| Component | Target Timeout | Action on Timeout |
| :--- | :--- | :--- |
| **API Endpoint** | < 15s | Return `504 Gateway Timeout`, log to Sentry |
| **DB Query** | < 5s | Abort query, retry up to 3 times, then fail |
| **External API** | < 8s | Circuit breaker fallback, return cached/stale data |
| **Queue Job** | < 30s | Move to DLQ after 3 retries |
| **Search Query** | < 150ms | Fallback to cached results |

### 23.6 Feature Flag Cache (Redis + Local Memory)
```typescript
// Two-tier cache to avoid DB hit on EVERY request
class FeatureFlagCache {
  private localCache = new Map<string, boolean>();
  private readonly LOCAL_TTL = 30_000; // 30s in-memory
  private readonly REDIS_TTL = 300; // 5m in Redis

  async isEnabled(flagName: string): Promise<boolean> {
    // 1. Check local memory (microseconds)
    const localValue = this.localCache.get(flagName);
    if (localValue !== undefined && Date.now() - localValue.ts < this.LOCAL_TTL) {
      return localValue.value;
    }
    
    // 2. Check Redis (milliseconds)
    const redisValue = await this.redis.get(`feature-flag:${flagName}`);
    if (redisValue !== null) {
      const parsed = JSON.parse(redisValue);
      this.localCache.set(flagName, { value: parsed, ts: Date.now() });
      return parsed;
    }
    
    // 3. Fallback to DB (ONLY if cache miss)
    const dbValue = await this.featureFlagRepo.isEnabled(flagName);
    await this.redis.setex(`feature-flag:${flagName}`, this.REDIS_TTL, JSON.stringify(dbValue));
    this.localCache.set(flagName, { value: dbValue, ts: Date.now() });
    return dbValue;
  }
}
```
